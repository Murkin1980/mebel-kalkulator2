# SALAMAT CALC — целевая архитектура PWA

Status: SPECIFICATION ONLY (DEV-CP-01). Ничего из описанного ниже, кроме независимого
модуля `shared/pricing/`, в CP-01 не реализовано.

Дата: 2026-10-20
Область: будущая миграция калькулятора в самостоятельное PWA на `calc.salamat-mebel.kz`.

## 1. Цель и границы

Цель — универсальный мебельный PWA-калькулятор, который:

- считает стоимость полностью на клиенте, без обязательного сервера;
- позволяет каждому мебельщику вести собственные тарифы, формулы и правила округления;
- работает офлайн (тарифы и история — локально);
- хранит историю расчётов, воспроизводимую по версии тарифа;
- допускает резервное копирование и перенос конфигурации через JSON.

Вне границ этой спецификации (и вне CP-01):

- перенос проекта в монорепозиторий;
- облачная БД, новые сервисы, аккаунты, синхронизация между устройствами;
- изменение действующего Express API, SQLite-схемы и таблицы `settings`;
- замена действующего калькулятора;
- Service Worker, манифест, Cloudflare-проект, реальный деплой.

## 2. Целевая схема

```
┌──────────────────────────── Браузер (PWA) ─────────────────────────────┐
│  React + TypeScript (существующий Vite SPA, client/src)                │
│      │                                                                  │
│      ├── shared/pricing  ← чистый движок (AREA/LINEAR/UNIT/COST_PLUS)   │
│      │        ▲                                                         │
│      │        └── профили тарифов (JSON, Zod-валидация, версии)         │
│      │                                                                  │
│      ├── IndexedDB: профили тарифов + история расчётов                  │
│      ├── Export/Import JSON: резервная копия и перенос конфигурации     │
│      └── Service Worker + Web App Manifest: офлайн-запуск и установка   │
└─────────────────────────────────────────────────────────────────────────┘
                    │ (опционально, не обязательно для расчёта)
                    ▼
        Существующий Express API (лиды, настройки) — без изменения контрактов
```

Ключевой инвариант: расчёт не требует сети. Сеть нужна только для необязательных
действий (отправка заявки, публикация обновления приложения).

## 3. Слои

### 3.1 Расчётное ядро — `shared/pricing/`

Уже реализовано в CP-01:

- чистые функции `calculatePrice(profile, request)`;
- четыре метода: `AREA`, `LINEAR`, `UNIT`, `COST_PLUS`;
- размеры в миллиметрах, деньги в KZT, точность 1 тиын;
- настраиваемое округление итога (`NONE` / `NEAREST` / `UP` / `DOWN` + шаг в KZT);
- дополнительные позиции и запрет двойного начисления включённых услуг;
- версионируемые профили тарифов с Zod-валидацией, экспортом и импортом JSON.

Ядро не зависит от Express, SQLite и React, поэтому его можно использовать в
браузере как есть — без сетевых запросов и без исполнения пользовательского кода.

### 3.2 Клиентский UI — React + TypeScript

Используется существующий стек (Vite, React 18, Tailwind, shadcn/ui, wouter,
TanStack Query). Новые UI-фреймворки не вводятся.

Будущие экраны (следующие checkpoint'ы, не CP-01):

1. Калькулятор: выбор профиля → категории → тарифной позиции → размеры/количество →
   дополнительные позиции → результат с разбивкой по строкам.
2. Редактор тарифов: таблица профиля, редактирование цен и правил округления,
   валидация перед сохранением.
3. История расчётов: список, повторный расчёт, экспорт.

### 3.3 Хранилище — IndexedDB

- Хранилище `profiles`: профили тарифов как JSON-документы, ключ — `profileId`,
  индекс — `version`. Старые версии профиля сохраняются, чтобы ранее выданные
  расчёты оставались воспроизводимыми.
- Хранилище `quotes`: история расчётов. Запись содержит запрос, результат и
  снимок профиля (`profileId`, `version`, `schemaVersion`, `updatedAt`).
- Доступ через стандартный `indexedDB` браузера; библиотека-обёртка не требуется,
  пока не появится реальная потребность.
- Схема хранилища версионируется; миграция выполняется при открытии БД.

Таблица `settings` в SQLite не расширяется и не переносится: тарифные профили —
отдельная сущность нового контура.

### 3.4 Офлайн — Service Worker

- Precache app shell (HTML, JS, CSS, иконки, шрифты) при установке.
- Стратегия: cache-first для статики, network-first для навигационных запросов с
  офлайн-фолбэком на кэшированный shell.
- Тарифы и история в офлайне берутся из IndexedDB, а не из кэша HTTP.
- Обновление: новый Service Worker активируется после подтверждения пользователем;
  одновременно показывается применённая версия профиля тарифа, чтобы устаревшие
  цены не выглядели актуальными.
- Service Worker не кэширует и не подменяет ответы действующего API лидов.

### 3.5 Web App Manifest

- `name` / `short_name`: «Salamat Calc».
- `start_url: "/"`, `scope: "/"`, `display: "standalone"`.
- Иконки 192/512 px, `theme_color`, `background_color`.
- `lang: "ru"`, ориентация — любая.
- Офлайн-режим и установка не требуют нативных обёрток.

### 3.6 Резервное копирование JSON

- Экспорт: профиль (или все профили) + история расчётов в один JSON-файл.
- Импорт: строгая Zod-валидация, отказ при некорректных ценах, единицах или
  версии схемы; импорт никогда не перезаписывает профиль молча — сначала показ
  различий, затем подтверждение.
- Формат совместим с `serializeProfile` / `deserializeProfile` из `shared/pricing`.

### 3.7 Деплой

- Отдельный проект Cloudflare (Pages) для статического клиента.
- Домен: `calc.salamat-mebel.kz`.
- Расчёт работает без бэкенда; API (лиды, настройки) подключается как
  необязательный внешний сервис по конфигурируемому base URL.
- Деплой и создание инфраструктуры в CP-01 запрещены.

## 4. Поток расчёта

```
ввод пользователя (мм, количество, позиции)
        │
        ▼
Zod-валидация запроса  →  ошибка с понятным кодом
        │
        ▼
calculatePrice(profile, request)   ← профиль из IndexedDB (локально)
        │
        ▼
результат: строки, subtotal, округление, total,
           profileId + profileVersion + schemaVersion
        │
        ▼
сохранение в историю (снимок профиля) → экспорт/заявка (опционально)
```

## 5. Инварианты

1. Тарифы — данные. Изменение цен не требует изменения кода движка.
2. Профили изолированы: расчёт использует только переданный профиль, глобального
   состояния тарифов нет.
3. Один и тот же профиль + запрос всегда дают одинаковый результат.
4. Результат всегда фиксирует применённую версию профиля.
5. Включённые услуги (фурнитура, изготовление, монтаж у Salamat Mebel) не могут
   начисляться повторно.
6. Нет `eval`, нет исполнения пользовательского JavaScript, нет сетевых запросов
   внутри расчёта.
7. Действующие контракты API (`/api/settings`, `/api/calculate`, `/api/leads`) и
   поведение текущего UI не меняются до отдельного одобренного checkpoint'а.

## 7. Риски и ограничения

- Локальные тарифы могут устареть: нужен явный индикатор версии профиля и
  напоминание об обновлении.
- Данные в IndexedDB привязаны к устройству и браузеру; без экспорта JSON они
  теряются при очистке хранилища.
- Расчёт полностью доверяет локальному профилю: цены должны подтверждаться
  владельцем, а не подставляться демонстрационными значениями.
- Офлайн-режим не должен блокировать обновление тарифов при появлении сети.
- PWA-контур не должен менять юридически значимые условия оферты без согласования.
